# セッションID仕様

## 目的

`pcdiag`が生成する収集結果、診断結果、レポートを、同一の診断セッションに属する成果物として安全に関連付けるための識別方法を定義する。

この仕様におけるセッションIDは、成果物を関連付けるための識別子であり、認証やアクセス制御を目的としたものではない。

## 採用方式

正式なセッションIDにはUUIDv4を使用する。

UUIDv7は採用しない。`pcdiag`の診断対象にはシステム時刻が正しく設定されていないPCも含まれる可能性があるため、IDの生成と一意性を対象PCの時刻に依存させない。

UUIDはRFC 9562に準拠する。

- 仕様: <https://www.rfc-editor.org/rfc/rfc9562.html>
- バージョン: UUIDv4
- 生成方法: 暗号学的に安全な乱数生成器を使用する
- 外部通信: 不要
- 端末固有情報: 使用しない

## 正式な文字列表現

JSONおよびRust内部で受け渡す正式なセッションIDは、小文字かつハイフンを含む標準的なUUID文字列とする。

```text
a3f17c92-d604-4be8-9ea7-6ab7b92e41c5
```

次の表現は正式形式として使用しない。

- 大文字のUUID
- ハイフンを除去したUUID
- 波括弧で囲んだUUID
- `urn:uuid:`を付けたUUID
- UUIDの一部だけを使用した値

読み込み時に正式形式以外を許容するかどうかは、スキーマの入力検証方針を決定する際に別途検討する。保存時には常に正式形式へ正規化する。

## 生成タイミング

セッションIDは診断セッションの開始時に1回だけ生成する。

```text
セッション開始
    ↓
UUIDv4を生成
    ↓
セッションディレクトリを作成
    ↓
collect
    ↓
diagnose
    ↓
report
```

一度生成したセッションIDは変更しない。`collect`、`diagnose`、`report`を別々に実行した場合も、既存セッションへ成果物を追加するときは元のセッションIDを引き継ぐ。

## 成果物間の関連付け

同一セッションに属するすべてのマニフェストへ、正式なセッションIDを記録する。

収集成果物:

```json
{
  "session_id": "a3f17c92-d604-4be8-9ea7-6ab7b92e41c5",
  "artifact": "collection"
}
```

診断成果物:

```json
{
  "session_id": "a3f17c92-d604-4be8-9ea7-6ab7b92e41c5",
  "artifact": "diagnosis"
}
```

レポート成果物:

```json
{
  "session_id": "a3f17c92-d604-4be8-9ea7-6ab7b92e41c5",
  "artifact": "report"
}
```

`diagnose`および`report`は、入力する成果物の`session_id`が一致することを検証する。異なる場合は処理を中止し、成果物を組み合わせない。

## 表示用ID

ディレクトリ名や画面表示では、正式なUUIDからハイフンを除去し、先頭12桁を表示用IDとして使用する。

```text
正式なセッションID:
a3f17c92-d604-4be8-9ea7-6ab7b92e41c5

表示用ID:
a3f17c92d604
```

表示用IDは正式な識別子ではない。成果物の照合には必ずUUID全体を使用する。

表示用IDは正式なUUIDから導出できるため、独立したフィールドとしてJSONへ保存しない。これにより、正式IDと表示用IDの不一致を防止する。

## セッションディレクトリ名

セッションディレクトリ名には、ローカル日時と表示用IDを使用する。

```text
pcdiag-<YYYYMMDD>-<HHMMSS>-<表示用ID>
```

例:

```text
pcdiag-20260715-103015-a3f17c92d604
```

ローカル日時は利用者が成果物を見つけやすくするための表示情報であり、セッションの正式な識別には使用しない。対象PCの時刻が誤っていても、UUIDv4によるセッションの一意性には影響しない。

ディレクトリ名だけを根拠に、成果物が同一セッションへ属すると判断してはならない。

## ディレクトリ作成時の衝突処理

セッションディレクトリは既存の成果物を上書きしないよう、次の手順で作成する。

1. UUIDv4を生成する。
2. UUIDから表示用IDを導出する。
3. ローカル日時と表示用IDからディレクトリ名を作る。
4. 同名のファイルまたはディレクトリが存在しないことを確認する。
5. 同名が存在する場合は、新しいUUIDv4を生成して再試行する。
6. 存在しない場合は、新規ディレクトリを作成する。

処理中は、正式なディレクトリ名へ`.incomplete`を付けた一時ディレクトリを使用する。

```text
pcdiag-20260715-103015-a3f17c92d604.incomplete
```

必要な成果物の書き込みが正常に完了した後、`.incomplete`を除いた正式名へ変更する。

## 一意性の範囲

正式な一意性はUUID全体によって確保する。表示用IDやディレクトリ名は、利用者が成果物を扱いやすくするための補助表現である。

- 正式な関連付け: UUID全体
- JSON内の保存値: UUID全体
- ディレクトリ名: 日時と表示用ID
- 画面表示: 必要に応じて表示用ID

## 機密情報の扱い

セッションIDの生成には、次の情報を使用しない。

- コンピューター名
- ユーザー名
- IPアドレスまたはMACアドレス
- PCやデバイスのシリアル番号
- Windowsのプロダクトキー
- ハードウェア固有ID
- 収集した診断情報

セッションIDから、診断対象PCや利用者を特定できる情報を導出できないようにする。

## セキュリティ上の制約

セッションIDおよび表示用IDは秘密情報として扱わない。

以下の用途には使用しない。

- 認証トークン
- 暗号鍵
- パスワード
- アクセス制御
- 電子署名
- 成果物の改ざん検知

成果物の完全性や改ざん検知が必要になった場合は、ハッシュ値や電子署名を別の仕組みとして設計する。

## 決定事項

| 項目 | 決定内容 |
|---|---|
| 正式なセッションID | UUIDv4 |
| JSON表現 | 小文字、ハイフンを含む標準UUID文字列 |
| 表示用ID | ハイフンを除去したUUIDの先頭12桁 |
| 表示用IDの保存 | 保存せず、正式IDから導出 |
| ディレクトリ名 | `pcdiag-<YYYYMMDD>-<HHMMSS>-<表示用ID>` |
| 成果物の照合 | UUID全体で行う |
| UUIDv7 | 使用しない |
| 端末固有情報 | ID生成に使用しない |
| 外部通信 | 不要 |
