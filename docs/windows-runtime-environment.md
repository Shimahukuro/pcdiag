# Windows常駐・自動実行環境コレクター

## 目的と情報源

起動遅延、常駐負荷、ソフトウェア競合、残存エントリ、反復するタスク失敗を調査するため、次の読み取り専用情報源を使用する。

| カテゴリ | 情報源 |
| --- | --- |
| サービス | CIM `Win32_Service` |
| スタートアップアプリ | CIM `Win32_StartupCommand` |
| インストール済みアプリ | 32/64ビットのUninstallレジストリ、AppX/MSIX |
| 実行中プロセス | CIM `Win32_Process` |
| スケジュール済みタスク | `Get-ScheduledTask`、`Get-ScheduledTaskInfo` |

MSIの再構成を誘発し得る`Win32_Product`は使用しない。収集中にサービス、プロセス、タスク、アプリ、レジストリを変更しない。

## 取得状態と上限

各カテゴリは独立して例外を処理する。一部カテゴリの権限不足や不正な参照先によって、他カテゴリの収集を中止しない。成功した空の列挙は`items: []`、取得不能は`items: null`とし、後者の理由を`status.json`へ記録する。

成果物サイズを制限するため、各カテゴリは最大5,000件を保存する。超過時は`truncated: true`とし、コレクターを`partial`にする。実行ファイルの署名とSHA-256は、同じ正規化済みパスについて1回だけ取得して再利用する。

## 保存と表示

`collection.json`の`runtime_environment`に5カテゴリを保存する。実行ファイル参照は共通の`binary`構造を使い、パス、発行元、署名状態、SHA-256、存在状態をカテゴリ間で比較できるようにする。

HTMLレポートは「常駐・自動実行環境」の中にカテゴリ別の折りたたみ一覧を表示する。初期実装では事実を表示するだけで、停止中、無効、発行元不明、署名不明を単独の理由として障害認定しない。

コマンドラインと引数は保存前に一般的な資格情報オプションをマスクする。詳細は[機微情報の取り扱い方針](sensitive-data-policy.md)を参照する。
