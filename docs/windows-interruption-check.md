# Windows中断処理の実機確認

## 前提

Windows上でデバッグまたはリリースビルドした`pcdiag.exe`を、コマンドプロンプトまたはPowerShellから実行する。各確認では新しい空の出力先を使用する。

終了コードは、コマンドプロンプトでは`echo %ERRORLEVEL%`、PowerShellでは`$LASTEXITCODE`で確認する。

## 確認項目

### collect

1. `pcdiag.exe collect --output <出力先>`を実行する。
2. 収集中に`Ctrl+C`を1回押す。
3. 終了コードが`130`であり、標準出力に成果物パスが出ていないことを確認する。
4. 生成済みのセッションが`.incomplete`で終わり、正式名のセッションが作成されていないことを確認する。
5. `.incomplete\interruption.log`に`stage: collect`と`status: incomplete`があることを確認する。

### diagnoseとreport

1. 完成済みの収集成果物を用意し、`diagnose`を実行して処理中に`Ctrl+C`を押す。
2. 同様に、完成済みの収集・診断成果物を用意し、`report`を実行して処理中に`Ctrl+C`を押す。
3. 終了コード、標準出力、`.incomplete`、`interruption.log`が`collect`と同じ規則に従うことを確認する。
4. 入力に使用した完成済み成果物が変更されていないことを確認する。

処理が短く中断確認点へ到達する前に完了する場合は、デバッガーで成果物書き込み直前または正式名への変更直前に停止してから`Ctrl+C`を送る。

### 一括実行

1. `pcdiag.exe --output <出力先>`を実行する。
2. `collect`、`diagnose`、`report`の各工程で個別に中断を試す。
3. 中断した工程より後の工程が開始されないことを確認する。
4. 中断前に完成していた工程の成果物が保持されていることを確認する。

### 2回目の中断

1. 実行中に`Ctrl+C`を2回続けて押す。
2. 2回目の要求後に終了コード`130`で直ちに終了することを確認する。
3. この場合、途中の書き込みと`interruption.log`は完成が保証されないことを確認する。
